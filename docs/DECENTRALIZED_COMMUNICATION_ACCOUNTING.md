# Decentralized Communication Accounting

Implementation `rvt_swarm/decentralized/comm_cost.py` ·
Tests `tests/test_communication_cost.py`

Every byte reported here is derived from an **explicit `struct` wire format**.
No figure comes from `sys.getsizeof`, `pickle`, `__sizeof__`, or any measurement
of a Python object. `assert_schema_sizes()` fails the suite if a declared schema
size ever diverges from `len(msg.payload_bytes())` of a real message.

---

## 1. Verified wire schemas

| message | fields | declared | measured | source |
|---|---|---|---|---|
| `beacon` | 11 | **49 B** | 49 B | `comms.Beacon.payload_bytes()` |
| `trigger` | 7 | **21 B** | 21 B | `epoch.TriggerMessage.payload_bytes()` |
| `score_consensus` | 7 | **20 B** | 20 B | `consensus.ScoreMessage` field list |
| `mode_confirmation` | 6 | **16 B** | 16 B | `epoch.ConfirmMessage.payload_bytes()` |

All four are `provisional: false, ok: true`.

### 1.1 A defect this table used to hide

Before the recovery audit, `trigger` and `mode_confirmation` were **provisional
and wrong**: `comm_cost.py` declared its own message classes with fields that did
not match `epoch.py`, giving **16 B** and **17 B** against the real **21 B** and
**16 B** — a 24 % undercount on trigger traffic. Two
`except TypeError: pass` handlers swallowed the constructor mismatch, so
`measured_bytes` stayed `None` and `verify_schema_sizes()` self-reported
`ok: false` to nobody, because **no test imported this module**.

Both schemas are now bound to `epoch.py`'s real encoders, a missing epoch module
raises `ImportError` instead of being skipped, and a regression test compares
against the live encoder rather than a hardcoded constant, so the two cannot
drift apart again.

## 2. Per-message field breakdown

**Beacon — 49 B.** `sender_id` u16 (2) · `timestamp_step` u32 (4) · `seq` u32 (4)
· `position` 2×f32 (8) · `velocity` 2×f32 (8) · `role_keep` 2×f32 (8) ·
`role_line` 2×f32 (8) · `committed_mode` u8 (1) · `epoch_id` u32 (4) ·
`degree` u8 (1) · `valid` u8 (1).

**Trigger — 21 B.** `sender_id` u16 (2) · `epoch_counter` u32 (4) ·
`trigger_flag` u8 (1) · token `(u32, u32, u16)` (10) · `timestamp_step` u32 (4).
The 10-byte `TriggerToken` is what the old 16-byte declaration was missing.

**Score consensus — 20 B.** `sender_id` u16 (2) · `epoch_id` u32 (4) ·
`round_index` u8 (1) · `z_keep` f32 (4) · `z_line` f32 (4) · `degree` u8 (1) ·
`timestamp_step` u32 (4).

**Mode confirmation — 16 B.** `sender_id` u16 (2) · `epoch_id` u32 (4) ·
`selected_mode` u8 (1, a mode-**set** code carrying the running min and max) ·
`margin` f32 (4) · `confirm_round` u8 (1) · `timestamp_step` u32 (4).

No message has a list-valued field. That is the structural reason no state can
travel more than one hop.

## 3. Cost model

With mean one-hop degree `d`, and `k_trigger = k_score = k_confirm = 4`:

| category | messages per robot per decision | bytes |
|---|---|---|
| trigger | `4 d` | `4 d × 21` |
| score consensus | `4 d` | `4 d × 20` |
| mode confirmation | `4 d` | `4 d × 16` |
| **per decision** | `12 d` | **`4 d × 57`** |
| neighbour discovery | 1 per control step | `49` B per step |

Worked example at the measured mean degree **d = 4.2** (N ∈ {4,6},
`r_comm = 3.0`):

| category | bytes / robot / decision |
|---|---|
| trigger | 352.8 |
| score consensus | 336.0 |
| mode confirmation | 268.8 |
| **total per decision** | **957.6** |

Neighbour discovery is continuous rather than per-decision: **49 B per robot per
control step**, i.e. **326.7 B/s** at `t_comm = 0.15 s`, or **5 880 B** over a
120-step episode.

## 4. What is measured versus what is schema-only

| category | schema verified | traffic actually generated by the runtime |
|---|---|---|
| neighbour discovery | yes | **yes** — `simulate_broadcast_round` |
| score consensus | yes | **yes** — `simulate_consensus` |
| trigger | yes | **no** |
| mode confirmation | yes | **no** |

`runtime.py` does not yet import `epoch.py`, so no trigger or confirmation
message is ever transmitted in a closed-loop episode. The byte costs above are
therefore **per-message costs multiplied by the protocol's declared round
counts**, not counts of observed packets. They are labelled as such rather than
presented as measurements. Wiring the epoch protocol into the runtime is Task 9;
until then the trigger/confirmation rows are a *budget*, not a *measurement*.

The beacon and score-consensus rows are real: those messages are generated,
delivered, gated by `r_comm`, dropped under packet loss, and counted.

## 5. Accounting invariants under test

- every schema's declared size equals the sum of its `FieldSpec` sizes;
- every schema's declared size equals `len(payload_bytes())` of a real message;
- `MessageAccountant` totals equal the sum of individual `wire_size()` values;
- the four categories are accounted separately and sum to the total;
- peak and average B/s derive from `t_ctrl = 0.15 s` and the message counts;
- `epoch_module_status()` / `reset_epoch_lookup()` behave correctly when the
  epoch module is absent.
